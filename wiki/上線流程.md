# 上線流程：最後一關由人決定

**一句話**：把新版放到正式網站給玩家玩叫「上線」。只有使用者說「上線」才上線；AI 負責上線前後的檢查。

## 上線前（AI 做）

1. `git status`、`git log`：要上的都已提交
2. 跑全部測試 `node --test tools/*.test.js` 和 `npm run build`，**有失敗就停下來，不上線**
3. 列出這次會上線的提交，每項一句話給使用者看
4. 看線上有多少人
5. 使用者說要寫更新公告才寫，先給他看、點頭才加

## 上線方式看「改了什麼、線上有沒有人」

| 情況 | 玩家感受 |
|---|---|
| 只改網頁 | 不斷線，網頁在安全的時候自己重新整理 |
| 改到伺服器，線上 0 人 | 直接重開 |
| 改到伺服器，有人在線上 | 跑馬燈倒數 60 秒，歸零才重開；玩家只中斷一次 |

只改網頁時，使用者 2026-11-21 定的規矩：**先確認線上已經是新版**（看 `version.json` 的版本編號），再開一個測試分頁確認畫面正常，才發公告。

## 上線後（AI 做）

1. 看伺服器狀態和錯誤紀錄
2. 把自己的 [[交接日誌]] 改成「已上線」
3. 回報：上了哪個版本、哪些還沒在線上實際試過

## 為什麼上線前後都要檢查

本機正常不代表正式網站正常，[[案例-人物變白]] 就是只在正式網站才出現的錯。
