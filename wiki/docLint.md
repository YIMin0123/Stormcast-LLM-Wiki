# docLint：檢查手冊有沒有過時的工具

**一句話**：`tools/docLint.mjs` 把手冊裡用反引號標起來的檔名、函式名、參數名，一個一個到程式裡找；找不到的就是「程式改了、手冊沒跟上」，列出來給 AI 改。

## 為什麼做這個（2026-11-23）

- 使用者問：檔案這麼大，是不是要一直搜尋？並給了 Karpathy 的 LLM Wiki 構想。
- AI 評估：專案本來就有 LLM Wiki 大部分的結構（[[CLAUDE-md]]、[[工程架構手冊]]、[[交接日誌]]），缺的是**定期檢查文件有沒有過時**，也就是 LLM Wiki 的 Lint 操作。
- 使用者：「做手冊檢查工具」。

## 怎麼用

```
node tools/docLint.mjs          檢查工程架構手冊
node tools/docLint.mjs --all    檢查所有手冊、準則、規則、流程、清單
```

找不到的印成「文件:行 `名字`」，有找不到的就失敗（exit code 1）。跑一次不到半秒。

## 第一次跑就抓到的過時處

- 手冊「看手上的平板」那條，寫的是早就拿掉的 `tabletCam`、`placeTabletDom`
- `marqCrown` 已改名 `marqPush`
- `pontoonY` 已改名 `deckY`

## 為了減少誤報

不報：有中文的、太短的、網址、萬用字元與佔位、前後寫著「已刪／拿掉／改名／以前」的（刻意寫的舊名字）、改版紀錄行、程式碼區塊。外部程式的名字在那一行加 `<!-- lint-ok -->`。

## 已知的限制

- 只查「名字還在不在」，**不查描述對不對**。
- 「原本」這類字剛好在附近時，真的過時的名字也會被放過（舊的 `matrix3d` 就是這樣漏掉的）。
- 沒有接進自動測試：文件過時不該擋住程式測試，收尾自己跑。

## 在流程裡的位置

被寫進 [[工程架構手冊]] 的維護協定第 5 項：改名、刪東西時，**收尾就跑**，不等到下一個 AI 被錯的手冊誤導才發現。這是「檢查往前移」的例子，見 [[開發迴圈]]。
