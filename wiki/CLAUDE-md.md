# CLAUDE.md：所有 AI 共用的專案規則

**一句話**：放在專案最外層的規則檔，Claude Code 每次開工會自動讀進來；其他 AI 也被要求照它做。它是 [[共用記憶]] 的第一層。

## 重點規則（整理自原文）

| 類別 | 規則 |
|---|---|
| 溝通 | 一律繁體中文；大改動前先跟使用者確認，只做講好的範圍 |
| 不寫死 | 地圖大小、島的位置等放 `src/config.js`，座標轉換用 `src/frame.js` |
| 分支 | 不開分支：所有 AI 直接在 `main` 上改、本地提交 |
| 多人同時改 | 改前先讀現行檔案；熱門檔（`src/main.js`、`index.html`、`src/config.js`）先 `git diff` 看有沒有別人的改動；提交前跑 `git diff --cached --name-status`，清單只能有自己的檔 |
| 伺服器 | 只准一組：網頁 5173、測試伺服器 8787，不准另開 |
| 實測 | 另開 `http://localhost:5173/?test` 分頁，不動使用者正在玩的分頁 |
| 上線 | 用 `bash deploy/push.sh`，**使用者說了才上線，也不要主動問**，步驟見 [[上線流程]] |
| 安全 | 不准提交密鑰、`.env`、玩家資料、`參考專案/` |
| 文件 | 開工先讀 [[工程架構手冊]]；改到結構，收尾要更新手冊 |
| 審查 | 使用者說「審查」才叫 codex、agy，見 [[審查流程]] |
| 交接 | 靠 `docs/日誌/`，見 [[交接日誌]] |

## 為什麼這樣定（推論）

- 「不開分支、都在 main 上改」：好幾個 AI 同時改同一個資料夾，用分支反而要一直合併；改成「只提交自己的檔」來避免互相蓋掉。
- 「使用者說了才上線」：上線會影響真的在玩的玩家，這一步一定要人決定。
