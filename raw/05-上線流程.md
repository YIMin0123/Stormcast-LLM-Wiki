# 上線流程（SOP）

2026-11-20 跟使用者討論定案。上線＝網頁＋遊戲伺服器都在 GCP 的 `valheim-tw`，用 `bash deploy/push.sh`（不經過 GitHub）。

## 什麼時候上線
- **使用者說「上線」才上線**。不主動問要不要上線。
- 只會上線已經提交的內容（push.sh 用 `git archive` 取出 HEAD 打包）。

## 上線前（AI 做）
1. `git status`、`git log`：要上的都已提交；別人做到一半、沒提交的不會被帶上去（不用處理，但要知道）。
2. 跑全部測試：`node --test tools/*.test.js`（Windows 上 `tools/` 整個資料夾會被當成一個檔、直接失敗）；跑 `npm run build`。有失敗就停下來告訴使用者，不上線。
3. 列出這次會上線的提交（上次上線之後的），每項一句話給使用者看。
4. 看線上人數：`curl -s https://35-229-248-193.sslip.io/status`。
5. **更新公告**（`src/announce.js` 的 `UPDATES`）：使用者說要寫才寫；要寫時先把文字給他看、點頭才加、提交。寫法照下面的「更新日誌寫法」。

## 更新日誌寫法（2026-11-21 使用者定）
給玩家看的 `UPDATES`：
0. **官方寫法、精簡**；可參考其他遊戲的更新日誌寫法。
1. 每條用「新增／優化／修正／調整」開頭，一句話講完，盡量 40 字內。
2. 只寫玩家看得到的結果；不寫程式、檔名、內部名稱，不寫原因與過程。
3. 不用口語：不用「我們」「你」、驚嘆號、表情符號。
4. 小 bug 不寫：修了也不列，也不合併成「修正若干已知問題」；只有玩家明顯感受得到的修正才寫。
5. 一次上線一筆：標題 12 字內、概括這次主題；條目照「新增 → 優化 → 修正 → 調整」排，最多約 6 條。
6. 數字照實寫（「500 公尺」「8 秒」）；名稱用遊戲裡的叫法（船隊、魚艙、按 E）。

例：「新增船隊共用魚艙：隊員可存取彼此的漁獲，售出收益仍歸釣獲者。」

## 選上線方式
| 情況 | 指令 | 玩家 |
|---|---|---|
| 只改了網頁（伺服器用不到的檔：畫面、介面、特效…） | `bash deploy/push.sh web`；**先確認線上已經是新版**：`curl -s https://35-229-248-193.sslip.io/version.json` 的 `v` 等於這次的提交編號（前 7 碼），再開一個 `?test` 分頁確認畫面正常（2026-11-21 使用者定）；確認了才發跑馬燈：`bash deploy/announce.sh "新版本更新"`，約 60 秒後 `bash deploy/announce.sh clear`（不帶倒數的公告會一直掛著，一定要清） | 不斷線、不踢人；網頁自己發現新版，安全的時候自動重新整理（2026-11-21 使用者：只換網頁也要發跑馬燈） |
| 有改到伺服器或雙端共用的檔（`server/`、`src/` 裡伺服器也 import 的，例如 `config.js`、`layout.js`、`fishdata.js`、`boatdata.js`），線上 0 人 | `bash deploy/push.sh` | — |
| 同上，有人在線上 | `bash deploy/push.sh --notice "新版本更新" --count 60` | 跑馬燈倒數 60 秒，**倒數到 0 才重開**（只重開一次、不會提早）；斷線後自動接回、自動換成新版網頁 |

不確定伺服器有沒有用到某個檔：查 `server/` 裡的 import。

## 玩家怎麼拿到新版（src/version.js）
- 打包時把提交編號寫進網頁程式（`VITE_BUILD`）和網站上的 `version.json`。
- 網頁每 2 分鐘、以及每次連上伺服器時比對 `version.json`；不一樣就等「安全的時候」自動重新整理：還沒進房，或連著線、沒在咬鉤／搏魚／拋竿蓄力、沒在打字、伺服器沒在倒數重開。
- 重新整理後照常接回房間：人和船回到海上原處、家當都在。
- 網址 sslip.io、nip.io 兩個都通；`deploy/stormcast.service`（允許的網址）有改的話要用完整上線才會換上去。
- 首頁和 `version.json` 不快取（`deploy/Caddyfile` 的 `@fresh`），重新整理一定拿到新版。Caddy 設定跟伺服器上的不一樣時，`remote-update.sh` 會印出差別、檢查語法、留 `.bak`、重新載入。
- 伺服器倒數重開（完整上線）：新網頁先在主機上備好，**跑馬燈倒數發出後才換上**（`remote-update.sh` 的 `later` 只備不換，`push.sh` 發完公告再叫 `web swap`）。倒數中網頁不會自己重新整理，所以玩家只在歸零那一刻斷一次。2026-11-22 以前是先換網頁、幾十秒後才發公告，那段時間網頁看到新版就自己重新整理，歸零又斷一次（使用者：「麻煩以後不要再發生」）；以後改上線程式要保住這個順序。倒數到了、伺服器重開斷線的那一刻，網頁直接重新整理拿新版（不先接回舊網頁），重新整理完不用按、自己接回原本那間房：**玩家只中斷一次**（2026-11-21 使用者）。以前是先斷線接回、20 秒後又重新整理一次，而且重新整理完停在填名字那頁要再按。

## 上線後（AI 做）
1. `/status` 正常；看伺服器紀錄有沒有錯誤：
   `gcloud compute ssh valheim-tw --zone asia-east1-b --tunnel-through-iap --quiet --command "sudo journalctl -u stormcast --since '5 min ago' --no-pager | tail -50"`
2. 把這次上線的開發日誌（`docs/日誌/`，只改自己的）狀態改「已上線」並寫日期，提交。
3. 回報：上線了哪個版本、包含哪幾項、哪些還沒在線上實際試過。

## 不做的事
- **GitHub**：使用者說推才推，上線不順便推（推 GitHub 也不會上線任何東西）。
- 版本號（給玩家看的）：使用者說先不要。
