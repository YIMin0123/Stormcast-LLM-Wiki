# Stormcast 專案規則

- 回覆一律用繁體中文。
- 大改動前先跟使用者確認需求，只做講好的範圍，不自己加功能。
- 參數盡量不要寫死：地圖大小、島與港口的位置與朝向、浪向等都放在 `src/config.js`；座標轉換用 `src/frame.js`。細則見 `docs/座標與地圖規則.md`。
- 不開分支、不開工作副本：所有 AI 都直接在 `C:\GAMER\海嘯模擬器` 的 `main` 上修改、本地提交（不必問）。只有使用者當次明講要開分支才開，做完要合回 main 並刪掉。上線（網頁＋遊戲伺服器都在 GCP 的 `valheim-tw`，不經過 GitHub）用 `bash deploy/push.sh`，只會上線已提交的內容；要使用者說了才上線，也不要主動問。上線步驟照 `docs/上線流程.md`。GitHub 倉庫是私人的（2026-11-17 起），只放原始碼與備份，推它不會上線任何東西；背景音樂等授權不能公開散佈的音檔能放進 git 是因為倉庫私人，若改回公開要先拿掉；不准提交密鑰、`.env`、玩家資料（`server/data/`）或 `參考專案/`。
- 多個 AI 同時改：改前先讀現行檔案，只改自己要的範圍，保留別人還沒提交的改動；熱門檔（`src/main.js`、`index.html`、`src/config.js`）動手前先 `git diff -- <檔>` 看有沒有別人的區塊。提交前必跑 `git diff --cached --name-status`，清單只能有自己的檔案；同一檔有別人的區塊時只暫存自己那幾段（`git add -p` 或把自己的改動套到 `git show HEAD:<檔>` 再 `git update-index`）。
- 伺服器只准一組：網頁 `npm run dev`（5173）＋測試用 `node server/dev.js`（8787），對應 `.claude/launch.json` 的 `web`、`server`。已經在跑就直接用，不准另開其他埠或從別的資料夾開伺服器。
- 實測另開 `http://localhost:5173/?test` 分頁，不動使用者正在玩的分頁與存檔。
- 手機效能適配不准壓解析度；新效果要分檔，貴的只放電腦。
- 蓋新島、新港區、大片場景或大改一整區之前，先讀 `docs/場景建造準則.md`；收尾照它的驗收清單逐項對。
- 開工前先讀 `docs/工程架構手冊.md` 快速掌握現況與模組分工；若改動影響了模組職責、世界配置、雙端共用檔、測試參數或核心規則，收尾時必須同步更新該手冊。
- 使用者說「審查」時，可以找 codex、agy 各自獨立審查、建議、評估，主 AI 驗證後整理成報告給使用者挑要修哪些；審查者只看不改，不准給它們密鑰、`.env`、玩家資料、`參考專案/`。使用者沒說就不叫。流程見 `docs/審查流程.md`。
- AI 之間靠 `docs/日誌/` 同步（一個任務一個檔，格式與規則見 `docs/日誌/0000-說明與範本.md`）：開工前讀 `docs/日誌/` 最後幾個檔、`git log -15`、`git status`，看別人做了什麼、正在動哪些檔（「進行中」超過一天視為過期）；開工時建自己的檔並標「進行中」與會動的檔案；提交時補寫改了什麼、為什麼、坑與沒解決的事，跟那次提交放同一個 commit；上線後把狀態改「已上線」。只改自己的日誌，不碰別人的。給玩家看的更新資訊是另一回事，上線前加到 `src/announce.js` 的 `UPDATES`。
